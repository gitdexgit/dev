# pg - What real failure looks like in programing  - A lesson in programmign - failing fast is good. Silent fail is the worst nightmare


In the industry, we call this a Silent Failure or a Logical Error, and it is the ultimate nightmare.

Here is why:

 Crashes are "Loud": If the program crashes, you get an error message and a line number. It’s like a smoke alarm—it’s annoying, but it tells you exactly where the fire is.

 Logical Errors are "Quiet": If the process is wrong but the procedure is "correct," the computer will happily calculate the wrong numbers for years. You might not realize your bank app is losing $0.01 on every transaction until the company is bankrupt.

The $125 Million Example:

In 1999, NASA lost the Mars Climate Orbiter.

 The Procedure: The code was perfect. It calculated thrust and trajectory exactly as written.

 The Process: One team used Metric units (Newtons), and the other used Imperial units (Pounds).

 The Result: The computer didn't crash. It didn't show an error. It just "perfectly" steered the spacecraft directly into the Martian atmosphere, where it burned up.

The Lesson:
This is why senior developers love it when code crashes early. We call it "Fail Fast." If it’s going to fail, you want it to explode immediately so you can fix the process before the garbage spreads.
